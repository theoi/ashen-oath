# ui/

Menus, HUD, settings, the controls screen and the story scene player.

## Input

`input/default_bindings.gd` (`DefaultBindings`) holds the default bindings from design §7 for
gamepad, keyboard + mouse and keyboard only, and the action names as constants. All three
schemes are active at once. The table is written into `project.godot` by:

```sh
godot --headless --path . -s "$PWD/tools/gen_input_map.gd"
```

`tests/ui/test_input_map.gd` fails if `project.godot` and the table drift apart.

Bindings follow design-lost-ark §2 (no chords). Gameplay actions, with the old ids kept so
content and other code stay valid: `move_left/right/forward/back`, `camera_left/right/up/down`
(aim: right stick or arrow keys; `AIM_*` constants), `attack_light` (basic, `BASIC`), `dodge`
(dash, `DASH`), `ability_1`..`ability_6` (skills, `SKILL_1..6`), `super` (awakening,
`AWAKEN`), `lock_on`, `target_next`, `pause`. Heavy, jump, guard and grab have no player
bindings. Menus use Godot's `ui_*` actions, extended with gamepad A (accept), B (back) and the
shoulder buttons (next/previous tab).

`presentation/input/device_input_source.gd` turns these into `SimInput` frames: buttons, the
camera-relative move stick, and the aim (mouse cursor ray-cast onto the floor, else the aim
actions, else the move direction). It sends the raw aim; aim assist and lock-on are the sim's.
`Binding.gamepad_chord` still supports pad chords (none by default) through
`DefaultBindings.held_ability_chord()` / `is_chord_consumed(action)`.

Ability slots are the table's `ability_1`, `ability_2`, ... actions
(`DefaultBindings.ability_actions()` / `ability_action(slot)`). The controls screen, HUD,
move list and prompts all read slots from there and from the fighter's `abilities`, so a
different slot count is a table change, not a UI change.

### Prompts

- `input/active_device.gd` (autoload `ActiveDevice`): the scheme the player last used
  (keyboard + mouse, keyboard only, gamepad) and the pad family (Xbox / PlayStation, from the
  joypad name). Emits `changed`. Force it for captures with `-- --device=gamepad|playstation|keyboard`.
- `input/input_glyphs.gd` (`InputGlyphs`): glyphs (Kenney Input Prompts) and plain text for an
  action in a scheme, derived from the bindings table, plus `MOVE` / `CAMERA` groups.
- `input/input_prompt.gd` (`InputPrompt`): a widget that draws an action's glyphs and redraws
  when the device changes.

## Move list

`movelist/move_list.gd` (`MoveList.build(data, rules)`) generates a fighter's move list from
its `FighterData` / `MoveData`, listing only what the default bindings can input: the basic
chain (following `next_light`), every skill slot with its type (tap, hold, charge, combo,
chain, dash-strike, stance: `MoveData.skill_type`, else read from the move), its follow-up,
⚡Counter mark and traits, the awakening and Burst costs, and dash (from `FighterData.dash`) or
the old roll. Traits such as "launches", "flinch immune" or "4 s cooldown" come from the move
data; only names and one-line descriptions come from `Roster`. The screen
(`movelist/move_list_screen.tscn`, `GameFlow.open_move_list(id)`) is reachable from the pause
menu and from versus select, and redraws its inputs when the device changes.

## Screens and flow

The main scene is `app/menu_app.tscn`: the 3D backdrop with a stack of menu screens on top.
The `GameFlow` autoload (`app/game_flow.gd`) owns navigation:

- `GameFlow.SCREENS` maps screen ids to scenes (`title`, `mode_select`, `story`, `controls`,
  `settings`, ...). `GameFlow.open_screen(id)` pushes one, `GameFlow.back()` pops one.
- `GameFlow.return_to_menu([&"mode_select", ...])` reloads the menus with a given stack, e.g.
  after a match.
- Story mode starts at the `story` screen (`story/story_entry.tscn`); see Story mode below.
- Dev runs can start deeper in the menus: `godot --path . -- --menu=mode_select,settings`.

Screens extend `MenuScreen` (`menus/menu_screen.gd`). Each returns the control to focus from
`default_focus()`, so every screen works with a gamepad or keyboard alone; `ui_cancel` goes
back. `make_button()` wires the confirm sound and focus-on-hover. `widgets/option_cycler.gd`
is a left/right selector for gamepad-friendly choices.

## Settings

The `Settings` autoload (`settings/settings.gd`) holds bus volumes (Master, Music, SFX, UI),
the default CPU difficulty and the unlock-all-fighters toggle. It saves to
`user://settings.cfg` (IndexedDB on the web build) and applies volumes to the audio buses.

## Theme

`theme/ashen_theme.tres` is the project-wide theme (`gui/theme/custom`), so every Control gets
the ember-and-ash look by default. It is generated by `tools/gen_theme.gd` from the colors in
`theme/palette.gd` (`Palette`, also used by HUD code):

```sh
godot --headless --path . -s "$PWD/tools/gen_theme.gd"
```

Label variations: `TitleLabel`, `HeaderLabel`, `SubheaderLabel`, `BodyLabel`, `StrongLabel`,
`SubtleLabel`, `HudNumberLabel`. Button variation: `MenuEntryButton`. Panel variation: `RowPanel`.
Fonts: Cinzel (headings, buttons) and Alegreya Sans (body).

## Versus and matches

- `versus/versus_select.tscn`: fighter, CPU opponent, arena (with variants) and difficulty.
  Locked fighters are listed but cannot be confirmed. `versus/roster.gd` (`Roster`) holds the
  display data plus each fighter's FighterData path and each arena's ArenaData and scene
  paths; `MatchSetup` uses stand-ins (test fighter, training arena) until those exist.
- `app/profile.gd` (`Profile` autoload): unlocked fighters, saved to `user://profile.cfg`.
  Story mode calls `Profile.unlock_fighter(&"morrigan")`. "Unlock all fighters" in
  Settings overrides it.
- `app/match_config.gd` (`MatchConfig`): the menu-level match description (fighters, teams,
  arena, difficulty, rounds, starting Soul, HP handicaps, where to return, and optional
  `on_finished` / `on_started` callbacks for story mode). `GameFlow.start_match(config)` opens
  `match/match_screen.tscn`, which builds the sim's `SimConfig` through `MatchSetup`,
  runs the sim's `MatchRunner` with a `DeviceInputSource` for the player and
  `MatchSetup.cpu_source()` for the others (the sparring partner until the CPU AI lands),
  and shows the fight through `FightView` (presentation/fight/) plus the HUD, pause menu and
  results. FightFx voices combat events; the match screen plays only round-flow sounds.
  `GameFlow.match_finished(result)` fires when the match ends.
- Dev runs: `godot --path . -- --match` (Aldric vs Morrigan) or `-- --match=1v2`.

## Story mode

Act 1, "The Bell Wakes", is data. `content/story/act1/act1.tres` (`StoryData`) lists the
steps in play order; each step is its own `.tres` next to it, a `StoryScene` or a
`StoryFight` (types in `content/types/story_*.gd`). To add a fight or a scene, create the
resource and insert it into `steps`; no code changes.

- `StoryScene`: the arena to dress (`arena` id), camera `shots`, `actors` (fighter id,
  position, facing, a clip of the shared KayKit set as the pose, optional held time, and the
  lines they are present for), extra `props`, and `lines` (`StoryLine`: dialogue with a
  speaker fighter id, narration without one, or a full-screen `CARD`; a line can switch
  shot and play a sound cue).
- `StoryFight`: player and opponents (two for a 1v2), arena, `rounds_to_win`,
  `round_seconds` (-1 = no timer), `ai_cap` (fight 1 is capped at Easy), per-opponent HP %
  and starting Soul, seed, `unlocks`, and in-fight `prompts` (`StoryPrompt`: the fight 1
  tutorial, ticked off from the player's fighter's sim events).

Flow:
- `story/story_entry.gd` (screen `story`): Continue, Begin / Start over, difficulty, and
  Chapter select (`story/story_chapters.tscn`, screen `story_chapters`) once the act is
  complete. Chapter replays do not touch the save.
- `story/story_director.gd` (`StoryDirector`, kept in `GameFlow.story_director` across scene
  changes) runs a `StoryRun` (`story/story_run.gd`: current step, difficulty, losses, save).
  Scenes open `story/story_player.tscn`; fights go through `GameFlow.start_match` with
  `MatchConfig.mode = STORY`, `on_finished` (results) and `on_started` (adds
  `FightPrompts` through `MatchScreen.add_overlay`).
- `StoryPlayer` shows a scene as stills (`StoryStage`: the arena scene, props, posed
  `StoryActorView`s and a fixed camera), the dialogue box with a portrait rendered live from
  the speaker's model (`StoryPortrait`), and title cards. Accept / Light / click advances,
  holding Back skips. After a fight it shows `StoryResultsScreen` (unlocks, difficulty,
  Continue) or `StoryHollowedScreen` (Retry, Retry on lower difficulty after two losses,
  Quit) over a still of the arena.
- Progress (`StorySave`, `user://story.cfg`) is saved after each won fight and at the end;
  fighters unlock through `Profile.unlock_fighter`.
- Actors and portraits use the fighter's `FighterData.scene` (a `FighterModel`, posed with
  `pose()`); a capsule stands in while a fighter has no model yet.

```sh
# Preview a scene (or a fight's results / loss card), optionally screenshot it under Xvfb
godot --path . res://ui/story/story_player.tscn -- --step=the_grave_witch --line=2
godot --path . res://ui/story/story_player.tscn -- --step=fight_gorrath --view=hollowed
# Play the whole act through the real game (menus, scenes, fights, retries, continue)
tools/story_playthrough.sh --fast=8 --skip-scenes
tools/story_playthrough.sh --fast=8 --force-after=20 --lose=fight_morrigan:2 --resume-after=fight_morrigan
tools/story_playthrough.sh --render --shots=/tmp/story-shots --line-seconds=1
tools/story_playthrough.sh --movie=/tmp/story.mp4 --quit-after-step=fight_two_hollowed
```
`tests/story/` covers the content, a scripted run of the whole act through `StoryDirector`
(saves, resume, unlocks, retries), the player's input handling and the tutorial prompts on
a real match.
## HUD

`hud/hud.gd` (`Hud`) draws a `HudState` (health with a trailing loss bar, guard gauge,
Soul with the Burst mark, ability cooldowns, timer, round pips) and announcements and
callouts from `MatchEvents`. `hud/sim_hud.gd` (`SimHud`) fills the HudState from the sim
and translates `SimEvent`s into `MatchEvents`, which also drive sounds
(`presentation/audio/match_sounds.gd`). Team 0 is on the left; extra fighters on a side get
compact plates (1v2). The skill bar (`hud/skill_bar.gd`, bottom center, design-lost-ark
§1.11) shows dash pips, one `SkillSlotView` per skill and the awakening with its Soul ring.
Each slot has its button for the active device, a radial cooldown sweep with seconds left, a
flash and chime when ready, grey-out when unusable, a ⚡ mark on counter skills, a draining
border and the follow-up's name while a combo or chain part waits, and a charge bar with
level marks and the perfect zone. Soul Burst lights on the dash (skill-kit fighters) or the
awakening button. SimHud reads the newer sim fields (`dash_charges`, `skill_next`,
`skill_window`, `charge_levels`, `perfect_start/end`) when they exist. Preview a mid-fight HUD:
`SCENE=res://tests/ui/hud_preview.tscn tools/capture_screenshot.sh /tmp/hud.png 40`.

## Feel tuning (pilot)

`tuning/feel_tuning.gd` (autoload `FeelTuning`) holds the design-lost-ark §1.13 values with
their defaults, persisted in `user://feel_tuning.cfg`. Presentation reads the live ones
(`FeelTuning.value(FeelTuning.CAMERA_PITCH)`, `SHAKE_SCALE`, `RUMBLE_SCALE`, `SLOW_MOTION`,
`CAMERA_DISTANCE / FOV / SMOOTHING / LEAD`, `flag(DAMAGE_NUMBERS)`; signal `changed`). The
sim ones (hitstop scale, skill speed, dash distance and charges) only reach a match through
`FeelTuning.apply_to(sim_config)` at match start, so replays record them and a running match
stays deterministic. The hidden panel (`tuning/tuning_panel.gd`) opens with Ctrl+Shift+F,
`?tune=1` on web or `-- --tune`, and has sliders, "Copy values" (text to paste back),
"Restart match" and "Defaults".
