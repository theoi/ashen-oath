# ui/

Menus, HUD, settings, the controls screen and the story scene player.

## Input

`input/default_bindings.gd` (`DefaultBindings`) holds the default bindings from design §7 for
gamepad, keyboard + mouse and keyboard only, and the action names as constants. All three
schemes are active at once. The table is written into `project.godot` by:

```sh
godot --headless --path . -s "$PWD/tools/gen_input_map.gd"
```

`tests/ui/test_input_map.gd` fails if `project.godot` and the table drift apart.

Gameplay actions: `move_left/right/forward/back`, `camera_left/right/up/down`, `attack_light`,
`attack_heavy`, `jump`, `dodge`, `guard`, `grab`, `ability_1/2/3`, `ability_modifier`,
`super`, `lock_on`, `pause`. Menus use Godot's `ui_*` actions, extended with gamepad A
(accept), B (back) and the shoulder buttons (next/previous tab).

Things input capture handles itself, because they are not plain actions:
- **Mouse camera:** `InputEventMouseMotion` while the mouse is captured.
- **Gamepad abilities** are chords: LT + X / Y / B. Use `DefaultBindings.held_ability_chord()`
  and skip light / heavy / dodge when `DefaultBindings.is_chord_consumed(action)` is true.
- **Right-stick flick** to switch target: watch the `camera_*` axis strength.

## Screens and flow

The main scene is `app/menu_app.tscn`: the 3D backdrop with a stack of menu screens on top.
The `GameFlow` autoload (`app/game_flow.gd`) owns navigation:

- `GameFlow.SCREENS` maps screen ids to scenes (`title`, `mode_select`, `story`, `controls`,
  `settings`, ...). `GameFlow.open_screen(id)` pushes one, `GameFlow.back()` pops one.
- `GameFlow.return_to_menu([&"mode_select", ...])` reloads the menus with a given stack, e.g.
  after a match.
- **Story mode entry point:** the `story` screen (`story/story_entry.tscn`) is a placeholder.
  The story mode replaces that scene or points `SCREENS[&"story"]` at its own.
- Dev runs can start deeper in the menus: `godot --path . -- --menu=mode_select,settings`.

Screens extend `MenuScreen` (`menus/menu_screen.gd`). Each returns the control to focus from
`default_focus()`, so every screen works with a gamepad or keyboard alone; `ui_cancel` goes
back. `make_button()` wires the confirm sound and focus-on-hover. `widgets/option_cycler.gd`
is a left/right selector for gamepad-friendly choices.

## Settings

The `Settings` autoload (`settings/settings.gd`) holds bus volumes (Master, Music, SFX, UI),
the default CPU difficulty and the unlock-all-fighters toggle. It saves to
`user://settings.cfg` (IndexedDB on the web build) and applies volumes to the audio buses.

## Theme

`theme/ashen_theme.tres` is the project-wide theme (`gui/theme/custom`), so every Control gets
the ember-and-ash look by default. It is generated by `tools/gen_theme.gd` from the colors in
`theme/palette.gd` (`Palette`, also used by HUD code):

```sh
godot --headless --path . -s "$PWD/tools/gen_theme.gd"
```

Label variations: `TitleLabel`, `HeaderLabel`, `SubheaderLabel`, `BodyLabel`, `StrongLabel`,
`SubtleLabel`, `HudNumberLabel`. Button variation: `MenuEntryButton`. Panel variation: `RowPanel`.
Fonts: Cinzel (headings, buttons) and Alegreya Sans (body).
